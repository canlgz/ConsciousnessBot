# 🧬 可塑性／學習層設計（一生之內的學習）

## 為什麼要這層

在「意識行為模擬」的盤點裡，最關鍵的缺口是 **一生之內的學習／可塑性**：

> 目前感覺鏈的參數、人格、路由全是固定程式碼；會動的只有內在熵（電量/飢餓/心情）的**短期漂移**，
> 而且 entropy 在重啟時半歸零。沒有任何機制讓「今天跟你聊的經驗」改變「明天它怎麼感覺、怎麼回」。
> 它唯一的「成長」靠**你改 code＋重生（蛻變）**——那是外部的，不是它自己學的。

本層的目標：讓 bot **跨重生持續累積對這位使用者的了解，並讓它改變未來行為**——
從「每次重生都差不多的我」往「**真的因為認識你而變得不一樣的我**」靠近。

這也是讓「自我」真正**連續**的那層：內在熵重啟半歸零（短期狀態），但**印痕（engram）持久化在
`state.json`、跨「死亡」延續**，是會被經驗改寫、卻不被重啟抹掉的長期自我。

## 核心隱喻：印痕（engram）＋ 強化 / 遺忘 / 固化

一條印痕 = 一個關於「我學到你什麼」的可加權記憶痕跡：

```
{"kind","key","value","weight"∈[0,1],"hits","born_ts","last_ts"}
```

- **強化（Hebbian-ish）**：同一訊號重複出現 → 權重往上補（飽和式 `w ← w + gain·(1−w)`，越強越難再長，避免單一條壟斷）。
- **遺忘（forgetting curve）**：時間衰減，半衰期 `_HALF_LIFE_S`（約 3 週沒被再強化 → 權重減半）。
- **固化（consolidation，像睡眠/記憶鞏固）**：定期把衰減寫回權重、修剪淡忘的（< `_FLOOR`）、每種類只留最強的幾條（`_MAX_PER_KIND`）→ store 永遠有界、且偏向「近期且反覆」的學習。

接地原則（沿用全專案精神）：印痕**只從真實訊號長出來**（使用者明講的偏好、真實的回返、真實情緒反應），
不臆造；bot 講得出「我學到你…（因為你上次…）」。

## 架構（讀寫兩面，與既有單一真相對接）

```
            capture（寫）                         recall（讀）
使用者訊號 ─────────────▶ EngramStore ─────────────▶ 行為改變
（明講偏好/回返/情緒）   (state.engrams,持久)      (grounding / routing / 感覺鏈)
                            ▲   │
                    reinforce │   │ consolidate（衰減＋修剪，像睡眠）
```

- **substrate**：`plasticity.py`（`reinforce` / `consolidate` / `top` / `_decayed_weight`），印痕存 `state.engrams`（隨 `state.json` 跨重生）。
- **寫**：`handle_message` 在路由解析後抽取訊號 → `reinforce`（並 `consolidate` 收斂、立即存檔）。
- **讀**：`plasticity.prefs_brief()` → 注入 `coach.build_memory_brief(learned=...)`，讓每次回覆都踩在學到的偏好上。
  （未來種類則注入 `intent.resolve`／感覺鏈參數。）

## 分期實作（每期可獨立上線、各自有測試）

### ✅ Phase 0：substrate（已實作）
`plasticity.py` 的 `Engram`/`EngramStore` 動力學（reinforce/decay/consolidate/top）＋ `state.engrams` 持久化。
測試：`tests/test_plasticity.py::SubstrateTest`（強化飽和、衰減修剪、top 取用衰減後權重）。

### ✅ Phase 1：相處偏好（已實作，端到端可用）
**最乾淨的學習迴圈**：使用者**明講的風格指示**就是監督訊號，效果就是 grounding 偏置。
- **capture**：`plasticity.read_preference(text)` 認出明講偏好（講短 `length`／具體 `detail`／別問太多 `questions`／別一直報數字 `stats`／輕鬆 `tone`）→ `reinforce(KIND_PREF, key, value=白話標籤)`。
- **recall**：`prefs_brief()` → 注入 brief 的「【我學到的相處偏好（…請盡量照著做）】」段，影響 `coach.reply`／`ask` 的每次回覆。
- **持久 & 連續**：印痕進 `state.engrams`、跨重生延續——重生後 bot 仍記得「你要我講短/別報數字」。
- 測試：`tests/test_plasticity.py`（偵測正負例、recall、**capture→存檔→死亡重生 reload→注入下一次回覆** 端到端）。

> 直接呼應前面那串截圖痛點：使用者一句「別一直報數字給我」會被**學起來**、之後少報——
> 不必每次都靠我改 regex；這正是「可塑性」要的：被經驗改寫。

### ⏳ Phase 2：主題親和（topic affinity）
- **capture**：使用者**一再回返**某主題（`datatools.best_topic` 命中）、或對某線**正向情緒反應**（reaction/mood delta 為正）→ `reinforce(KIND_TOPIC, 主題名, +)`。負向則弱化或記一條「少碰」。
- **recall**：① grounding 注入「我知道你最在意的線是…」；② 主動出聲（`spontaneous`）/自我刺激繞回時**優先挑高親和主題**；③ 收尾語氣。
- 風險防護：只在有明確 focus 主題時寫；衰減確保舊熱情會淡。

### ✅ Phase 3：路由更正記憶（learned corrections）（已實作）
把「被誤路由後又澄清」的修正**學起來**，而非全靠硬寫 regex——被你糾正過，下次同句式自己路由對。
- **capture**（`monitor._learn_route_correction`）：偵測**不滿訊號**（`plasticity.is_dissatisfaction`：看不懂／不是這個意思／你又會錯意／我是說…）緊接在某次回覆後 → 代表**前一句**被誤路由。兩種形態都接：① 不滿＋改寫**同一句**（「我是說，多久沒聊」＝dissat＋已是明確路由）當場學；② 純不滿（「看不懂」）先記、**下一句**改寫到明確路由再學。綁定 `learn_correction(signature(誤路由句) → 正確 route)`（route 須在 `SAFE_LEARN_KINDS`）。
- **recall**（`intent.resolve(text, ref, engrams)`）：先跑既有優先序得自然路由；**只當自然路由是泛用 fallback `fact_or_chat`** 且這句命中夠強的 correction 印痕 → 改用學到的 route。
- **安全閥（多重）**：① **只救 fallback**＝絕不覆蓋任何明確意向（不會劫持 `self_identity`/`self_state`…）；② route 限 `SAFE_LEARN_KINDS`（絕不學成身分等）；③ **需約兩次一致才生效**（gain 0.34 vs 門檻 0.5）＝一次意外不立刻改路由；④ 半衰期遺忘＝錯誤/過時的更正會自己淡掉；⑤ `signature` 最短長度避免亂命中；⑥ **`/forget`（/忘記）一鍵清除**所有學到的偏好與更正。
- 測試：`tests/test_corrections.py`（不滿偵測／signature／白名單拒學／兩次才生效／子字串命中／衰減淡忘／**只救 fallback 不劫持明確意向**／capture 端到端／/forget）。
- 限制（刻意）：v1 只救 `fact_or_chat`（最常見、最安全的誤路由桶——截圖那種掉進 function-calling 吐 stats 的就是它）；要覆蓋「誤路由到某個**明確但錯**的意向」留待後續、需更嚴門檻。

### ✅ Phase 6：自我表達可塑性（自我遞迴學習）（已實作）
**動機（截圖痛點＋誠實不變式）**：被問「你是誰／台詞都一樣會不會累」時 bot 自陳「我也在學習、在演化，希望能找到更多方式表達自己」。但原本唯一的去台詞機制（`_self_voice_mod`＋`recent_self_openers`＋`self_asks`）是**純記憶體、淺、窗內、重啟即歸零**——這句「我在學習、在演化」背後沒有任何耐久的東西支撐。本期把它變成**真的、且跨重生耐久**：bot 描述自己→把自我母題捕捉進耐久調色盤→調色盤反過來塑造下一次自我描述→使用者反應再加權→跨重生不斷循環。

- **capture**：
  - `plasticity.extract_self_motifs(text)`（`plasticity.py`）：從一段 bot 自我描述抽「自我形象母題」。用**精選母題詞表**子字串比對（複合詞如『閉合的迴圈/生命迴圈/陪你記寫/養成脈絡/會死會重生』直接認；單一高頻詞如『會餓/存在/醒來』須帶第一人稱自指前綴『我/自己』才算）。去重、有上限（4）。
  - `plasticity.capture_self_expression(engrams, text, now_ts)`：抽母題→對每個 `reinforce(KIND_SELFEXPR, key=母題)`。用越多權重越高＝越像台詞。
  - 接線（`monitor.py`）：`_record_self_opener`／`_capture_self_motifs`（旗標開時）在**所有自我路由送出後**捕捉，並記成 `state.recent_self_motifs`（附 ts、最後 8、持久化＝抱怨歸因能跨重啟存活）。`_record_self_opener` 涵蓋 10 條 voice-/reply-based 路由；`self_experience`、`self_state`（兩 `_say` 分支）不走 `_record_self_opener`，各自呼叫 `_capture_self_motifs`。
  - **抱怨監督**：`plasticity.is_repetition_complaint(text)`（台詞都一樣/又是這套/講過了/換個說法…）→ `mark_stale(engrams, 窗內 recent_self_motifs)` 用較大 gain（0.6）登記成**重度用爛**。落點在 `handle_message` 的 `_learn_route_correction` **之前**、與其互斥（線索與 `_DISSAT_CUES` 零交集），抱怨自我重複不污染 `KIND_CORRECTION`。只強化 `REACTION_WINDOW_SEC` 窗內的母題（逾窗不歸因＝陳年母題不被當「剛用的」誤強化）。
- **recall**：`plasticity.selfexpr_vary_brief(engrams, now_ts)` 取衰減後最重（最用爛）的幾個母題→一段**耐久換句話**提示，由 `_self_voice_mod` 併進既有 `parts`（與 `persona.vary_hint` 並存）。耐久調色盤現在能跨重生驅動變化。不夠強回 `''`（沒學到就不宣稱）。**門檻 `_SELFEXPR_VARY_MIN=0.5`**＝飽和加權下單次用過僅 0.34（不算台詞），反覆 ≥2 次（0.564↑）或被抱怨 `mark_stale`（0.6）才達標——如此提示語「你長期下來很常用 X」**有所本**（真反覆/被嫌才說），不用「一次出現」撐「長期老這樣」的空宣稱（與路由更正層 `_CORR_ACTIVE=0.5`『約兩次才生效』同一條接地精神）。
- **接地／誠實不變式**：母題只從**真實送出過的自我描述文字**抽取（純函式、不用 LLM、不捏造）。**詞表是『已知台詞母題』的近似清單、非 LLM 動態抽取**；召回只在真有捕捉＋衰減更替時才驅動「我在學著換說法」框架，否則**安全預設＝不明講**，讓耐久換句話本身使這句不證自明（Design 階段否決『明講引用』為預設）。`vary_brief` 文案層**硬寫**『只換措辭和角度、不要改變你是什麼』守住 `self_identity` 安全線：避開的是**用爛的措辭**、不是被接地的身分內容。
- **持久 & 連續（核心證明）**：`KIND_SELFEXPR` 印痕進 `state.engrams`、跨重生延續；用爛的台詞會隨半衰期淡掉、之後可重新當新鮮的用＝真正的「演化／更替」。飽和加權／衰減／固化由既有 substrate 保證有界（`_MAX_PER_KIND=12` 自然分桶、不擠掉其他 kind）。
- **旗標**：`SELFEXPR_PLASTICITY_ENABLED`（預設 True）。關＝capture/recall/mark_stale 三處提早 return／不進 `parts`＝**逐位元等同現行純記憶體去台詞行為**。
- **`/forget`**：engrams 整列清掉已順帶清掉 selfexpr 印痕；另清 `state.recent_self_motifs`（否則 /forget 後第一次抱怨仍會 mark_stale 殘留母題）；文案更新含『我學著怎麼表達自己的那些印痕』。
- 測試：`tests/test_selfexpr_plasticity.py`（母題抽取正/負例、只認精選母題、引用使用者話不誤抓；capture→reinforce；抱怨偵測 vs 誤路由不滿消歧（同句不同時為 True）；mark_stale 抬高避開度；vary_brief 格式/空集/門檻下回空；**capture→存檔→死亡重生 reload→recall 仍避開用爛母題**＝跨重生耐久核心證明；**旗標關＝逐位元等同**；/forget 清乾淨；consolidate 不擠掉其他 kind）。

### ✅ Phase 7：對話教學（taught skill）（已實作，預設關＝實驗灰度）
- **動機**：使用者**透過對話教 bot 學會做某事**——談到逐漸凝聚的共識時，把剛剛的教學對話經 LLM 轉譯成「下次同情境的回應做法 prompt」，存成可重用做法。設計決策：**bot 提議、你確認**（不自作主張）／學「**回應/表達的做法**」（注入 `coach.reply` 的 `extra_system`、只染語氣角度）／「**同主題/情境再現**」才召回（topic/intent 子字串比對、非 embedding）。
- **capture**：`plasticity.capture_skill(engrams, route_kind, topic_tag, prompt)`＝淨化→`reinforce(KIND_SKILL, key=_skill_key(route_kind, topic_tag), value=淨化後 prompt)`。key＝`{route_kind}|{signature(topic_tag)}`（topic 太短/None→段空＝泛用做法）。`gain=0.6`＝點頭是強監督、單次確認即達門檻（提議→確認兩步本身就是安全閘）。
- **recall**：`plasticity.recall_skill(engrams, route_kind, topic_tag)`＝`route_kind` 段精確相等 ∧（已存 topic 簽章夠長且為當前訊息簽章子字串＝單向，仿 `recall_route`）∧ 衰減後 ≥`_SKILL_ACTIVE`(0.5)；多條取權重最高。無 topic 段做法不在泛用桶 `fact_or_chat` 召回；當前無有效主題簽章＋`fact_or_chat` 保守不召回。由 `monitor._skill_extra` 包成 `coach.reply` 的 `extra_system`，只在 `SKILL_INJECTABLE_KINDS`(smalltalk/elaborate_prior/self_appraisal/fact_or_chat) 注入。
- 🛡️ **注入安全＝多層（誠實標註）**：`sanitize_skill_prompt` 是**所有讀 `KIND_SKILL.value` 的唯一程式出口**（capture 前、recall 後、`/skills` 都過），但它是**盡力而為的拒收清單（denylist、defense-in-depth），不是窮舉白名單**——自然語言無法以確定性黑名單窮舉所有破格/接地覆寫換句話（對抗式審查已證可繞、已大幅擴充清單）。真正把關靠三層：① 上游受限 LLM（`SKILL_DETECT_SYSTEM` 只蒸餾語氣做法）；② 提議→確認兩步；③ 預設關。命中破格/提權/改身分/接地覆寫/計算承諾紅旗、或過長(>200)/空 → 整條拒收回 ''。skill 只准管語氣/風格/角度，**絕不得改寫接地與承諾這些不變式**。
- 主題簽章用 skill 專屬 `_skill_topic_sig`（最短 `_SKILL_TOPIC_MIN`=2、不套 correction 的 5 字下限，短主題如「失眠」也能學/召回；`fact_or_chat` 桶無有效主題＝召不回 → `capture_skill` 誠實回 False、不給假 ack）。
- **提議·確認（Phase B）**：`coach.detect_skill_consensus`（專屬結構化 pass、保守）凝出共識 → `_maybe_propose_skill` 提議「要學成做法嗎」設 `skill_pending`（記憶體態、不持久化）→ 下一輪 `_handle_skill_confirm` 在分派前判讀**窄門檻**點頭（排除讚美）/婉拒/逾窗。前置門檻 `dialogue_intent.worth_skill_consensus`（需「以後/這種時候…」線索）＋冷卻＋待確認中不再提議。
- **旗標**：`SKILL_RECALL_ENABLED`（召回注入）／`SKILL_CONSENSUS_ENABLED`（提議偵測），**皆預設關**＝逐位元同現狀。`/skills` 檢視已學做法；`/forget` 連 `skill_pending`/冷卻歸零。
- 測試：`tests/test_taught_skill.py`（淨化白名單各紅旗/`_skill_key` None-safe/capture·recall 往返/單向主題/route 不符/無主題桶區隔/衰減/consolidate 保留/`/skills`；確認婉拒窄門檻排除讚美；前置門檻；detect 解析；`_skill_extra` 旗標兩態；提議冷卻·待確認·前置·紅旗阻擋；確認 capture·婉拒·逾窗·窗內模糊保留）。

### ⏳ Phase 4：固化「睡眠」週期
- 現在 `consolidate` 在每次 capture 後跑（store 恆有界）。Phase 4 把它接到**生命迴圈的閒置/每日摘要**那拍當「睡眠鞏固」：閒著時把當天的印痕衰減+鞏固，並可把**反覆強化**的短期偏好「升格」成更穩的長期印痕（提高其 floor/半衰期）。呼應死亡→重生隱喻：醒著學、睡時固化。

### ⏳ Phase 5：感覺鏈的個體化敏感度（per-user plasticity）
- **動機**：讓 bot 對「**這位使用者**怎樣才算一條線成形」逐漸調準。
- **capture**：長期統計這位使用者語料的序參數分佈、以及哪些湧現被使用者認可/否認 → 學一個 per-user 的 `k`/`tau` 偏置印痕。
- **recall**：`monitor._chain_params` 疊加這個學到的偏置（在現有 `k_breath`/`override` 之外，最低優先、幅度受限）。
- 最具「感覺真的長進」的一期，但動到核心判定，需最謹慎、最多回歸測試。

## 邊界與安全
- **接地**：印痕只從真實訊號長出來；bot 可據實說「我學到你…（因為你上次說過…）」。
- **有界**：飽和加權＋衰減＋固化上限 → store 不會無限膨脹或被單一訊號帶飛。
- **可逆/可檢視**：偏好/印痕是純資料，存在 `state.engrams`；可加 `/forget` 指令清除或調權重。
- **不越線**：學到的偏置**永不覆蓋**安全與身分規則（`self_identity` 絕不破格、感覺接地不捏造）；Phase 3/5 的自動偏置都設高門檻與幅度上限。
- **隱私**：印痕只關於與這位 owner 的相處，跟著 `state.json`，不寫共享 Drive。
